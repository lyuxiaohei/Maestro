# 架构评审

## 触发条件

- 用户要求评审架构设计（"评审一下架构"、"架构审查"）
- 架构设计完成后进入架构评审阶段（P11）
- 用户提供架构设计文档并要求评审
- 用户提到 architecture-review

## 执行流程

### 步骤 1：评审材料准备

- 收集架构设计文档（Phase 10 输出）及相关上游文档
- 确认评审范围：模块拆解、数据库设计、API 设计、流程设计
- 准备评审检查清单（技术可行性、扩展性、安全性三个维度）
- 输出：评审材料清单和评审计划

### 步骤 2：技术可行性评审

- 评估架构方案与现有技术栈的兼容性
- 检查技术选型的成熟度和社区支持
- 分析关键路径的技术实现风险
- 验证数据库设计和 API 设计的合理性
- 输出：技术可行性评审意见

### 步骤 3：扩展性评审

- 评估架构的水平/垂直扩展能力
- 检查模块边界是否支持独立部署和演进
- 分析数据库设计的扩展瓶颈（分库分表预留）
- 评估 API 版本管理的向前兼容性
- 输出：扩展性评审意见

### 步骤 4：安全性评审

- 检查认证鉴权方案的安全性
- 评估数据加密（传输和存储）策略
- 分析 API 接口的越权和注入风险
- 检查敏感数据的保护措施和合规性
- 输出：安全性评审意见

### 步骤 5：评审报告生成

- 汇总三个维度的评审意见
- 按严重程度分级：阻塞 / 重要 / 建议
- 每个问题附上改进建议和优先级
- 生成评审报告，明确是否通过或需修正
- 输出：架构评审报告

## 输入输出规范

**输入：**
- 架构设计文档（Phase 10 输出）
- 方案设计文档（Phase 09 输出，可选）

**输出：**
- 架构评审报告（含问题清单和改进建议）
- 评审结论（通过 / 有条件通过 / 需修正）
