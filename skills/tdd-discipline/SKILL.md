# TDD 纪律 — Test-Driven Development

## 铁律

```
没有失败的测试在前，禁止写任何生产代码
```

代码先于测试写出来了？删掉。从头开始。没有例外。

## 适用范围

**永远适用**: 新功能 / Bug 修复 / 重构 / 行为变更

**例外（需用户明确批准）**: 一次性原型 / 代码生成器产出 / 配置文件

## RED-GREEN-REFACTOR 循环

### RED — 写失败测试

写一个最小测试，描述应该发生什么。一个行为、名字清楚、真实代码（除非不可避免否则不 mock）。

### 验证 RED — 看它失败（强制）

| 语言 | 命令 |
|------|------|
| Java | `mvn test -Dtest={ClassName}#{methodName}` |
| React/TS | `npx vitest run {path/to/test}` |
| Python | `pytest {path/to/test}::{test_func}` |

确认测试**失败**（不是 error），失败信息符合预期，原因是缺少功能。

### GREEN — 最小实现

写最简代码让测试通过。不加功能、不重构、不"顺便改进"。

### 验证 GREEN — 看它通过（强制）

确认测试通过、其他测试仍通过、输出干净。失败时改实现不改测试。

### REFACTOR — 清理

只在绿色之后：去重、改名、抽辅助函数。不增加新行为。每次改动后重跑测试。

## 好测试的标准

| 维度 | 好 | 坏 |
|------|----|----|
| 最小 | 一件事。名字带 "and"？拆开 | `test('校验邮箱和域名和空白')` |
| 清楚 | 名字描述行为 | `test('test1')` |
| 意图清晰 | 展示期望的 API | 把代码该做啥盖住了 |

## 完成前检查清单

- [ ] 每个新函数/方法都有测试
- [ ] 每个测试都**实际看到过**失败
- [ ] 每个测试因正确原因失败（缺功能，非拼写错误）
- [ ] 每段实现都是**最小代码**让测试通过
- [ ] 全部测试**实际跑过**且通过
- [ ] 输出干净（无 error、无 warning）
- [ ] 测试用真实代码（mock 仅在不可避免时）
- [ ] 边界和异常路径已覆盖

不能全部勾选 = 跳过了 TDD = 重来。

## 卡住时

| 问题 | 解法 |
|------|------|
| 不知道怎么测 | 先写期望的 API、先写断言、问用户 |
| 测试太复杂 | 设计太复杂，简化接口 |
| 必须 mock 一切 | 代码耦合太严重，用依赖注入 |
| 测试 setup 巨大 | 抽辅助函数，还是复杂就简化设计 |
