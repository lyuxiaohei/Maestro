# 详细设计

## 触发条件

- 用户要求进行详细设计（"写详细设计"、"接口设计文档"）
- 架构细化完成后进入详细设计阶段（P13）
- 用户提供最终架构文档并要求展开详细设计
- 用户提到 detailed-design

## 执行流程

### 步骤 1：需求拆解

- 读取最终架构文档（Phase 12 输出），将模块拆解为可实现的开发单元
- 每个开发单元定义明确的功能边界和验收标准
- 识别开发单元间的依赖关系和集成点
- 输出：开发单元清单（含功能边界和依赖关系）

### 步骤 2：技术选型

- 针对每个开发单元确定具体技术方案（框架、库、中间件）
- 评估备选方案的成熟度、性能、社区活跃度
- 记录选型决策和理由（详见 `references/design-template.md`）
- 输出：技术选型决策表

### 步骤 3：模块详细设计

- 为每个模块定义内部结构：类/服务/函数的职责划分
- 设计模块内部的状态管理和数据流转
- 定义模块的配置项和初始化流程
- 输出：模块内部设计文档

### 步骤 4：接口详细设计

- 细化 API 接口定义：完整请求/响应 Schema、错误码、幂等性
- 定义内部模块间的调用接口（函数签名、事件格式）
- 设计接口的限流、熔断、重试策略
- 输出：接口详细设计文档

### 步骤 5：数据库详细设计

- 细化表结构：字段类型、长度、默认值、约束条件
- 设计索引策略（查询场景分析）、分区策略
- 编写 DDL 语句和数据迁移方案
- 输出：数据库详细设计文档（含 DDL）

### 步骤 6：流程详细设计

- 细化业务流程：补充异常分支、超时处理、并发控制
- 设计事务边界和一致性保证策略
- 编排异步任务和定时任务的执行计划
- 输出：流程详细设计文档

### 步骤 7：测试策略

- 为每个开发单元制定测试策略：单元测试、集成测试、端到端测试
- 定义关键测试场景和预期结果
- 规划测试数据准备和 Mock 策略
- 输出：测试策略文档

## 输入输出规范

**输入：**
- 最终架构文档（Phase 12 输出）

**输出：**
- 详细设计文档（含模块/接口/数据库/流程详细设计）
- 技术选型决策表
- 数据库 DDL 语句
- 测试策略文档
