# 问题严重程度分级标准

## P0 — 致命（必须立即修复）

- SQL 注入、XSS、CSRF 等安全漏洞
- 数据丢失或损坏风险
- 认证/鉴权绕过
- 硬编码密钥或凭据

## P1 — 严重（本轮必须修复）

- 功能逻辑缺陷导致错误结果
- 性能瓶颈（N+1 查询、全表扫描、内存泄漏）
- 异常处理缺失导致服务不可用
- 事务边界错误导致数据不一致
- API 契约与实现不匹配

## P2 — 一般（建议修复）

- 命名不规范、代码重复
- 缺少必要的日志或注释
- 错误提示不友好
- 硬编码配置项（应提取为常量/配置）
- 缺少输入参数校验

## P3 — 建议（可选优化）

- 代码可读性优化
- 性能微优化（非关键路径）
- 最佳实践建议
- 测试覆盖率提升建议

## 审核报告格式

```markdown
## 代码审核报告

### 统计

| 级别 | 数量 |
|------|------|
| P0 致命 | X |
| P1 严重 | X |
| P2 一般 | X |
| P3 建议 | X |

### 问题详情

| 编号 | 级别 | 文件 | 行号 | 问题描述 | 修复建议 |
|------|------|------|------|---------|---------|
| R-001 | P1 | service.js | L42 | N+1 查询 | 使用 JOIN 或批量查询 |
```
