# 代码审核

## 触发条件

- 用户要求审核代码（"审核这段代码"、"代码审查"）
- 前后端开发完成后触发 AI 审核（P15）
- 用户提到 code-review

## 执行流程

### 步骤 0：代码索引上下文（可选）

审核开始时检查 `.planning/code-index.json` 是否存在。若存在，运行 `node scripts/code-graph-scan.js . --context --dirs {changed_file_dirs}` 获取变更文件的依赖关系，作为审核补充上下文。索引不存在时跳过此步骤。

### 步骤 1：审核范围确认

- 确认审核范围（后端/前端/全栈）
- 读取相关源代码文件和设计文档
- 输出：审核范围清单

### 步骤 2：后端代码审核

- 安全审核：SQL 注入、权限绕过、敏感数据泄露
- 性能审核：N+1 查询、缓存策略、连接池使用
- 规范审核：命名、异常处理、事务管理
- 输出：后端审核发现列表

### 步骤 3：前端代码审核

- 安全审核：XSS、CSRF、Token 处理、敏感信息存储
- 性能审核：重渲染、包体积、懒加载
- 规范审核：类型安全、组件拆分、状态管理
- 输出：前端审核发现列表

### 步骤 4：问题分级

- 将所有审核发现按严重程度分级（详见 `references/severity-guide.md`）
- P0（致命）：安全漏洞、数据丢失风险
- P1（严重）：性能瓶颈、功能缺陷
- P2（一般）：代码规范、可维护性
- P3（建议）：优化建议、最佳实践
- 输出：分级问题清单

### 步骤 5：审核报告

- 汇总审核结果，生成结构化审核报告
- 包含问题统计、详细问题列表、修复建议
- 输出：代码审核报告

## 输入输出规范

**输入：**
- 源代码文件（后端/前端）
- 详细设计文档（Phase 13，可选）

**输出：**
- 代码审核报告（含分级问题清单和修复建议）
