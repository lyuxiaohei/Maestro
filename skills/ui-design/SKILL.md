# UI 设计

## 触发条件

- 用户要求制定 UI 设计规范（"设计规范"、"UI 设计"、"界面设计"）
- 原型复核完成后进入 UI 设计阶段（P08）
- 用户提供原型 HTML 并要求生成设计稿
- 用户提到 ui-design

## 执行流程

### 步骤 1：设计规范制定

- 接收原型 HTML、功能清单、复核报告
- 分析原型页面结构，提取设计要素（布局模式、交互类型、信息密度）
- 确定设计风格方向（专业/活泼/极简等）
- 输出：设计规范概要（风格定位、设计原则、约束条件）

### 步骤 2：色彩与字体定义

- 基于设计规范，定义色彩体系和字体层级
- 色彩体系：主色、辅助色、功能色（成功/警告/错误/信息）、中性色梯度
- 字体层级：标题/正文/辅助文字的字号、字重、行高
- 输出：设计系统 Token 定义（详见 `references/design-system.md`）

### 步骤 3：组件库设计

- 根据功能清单和原型，梳理所需组件清单
- 设计每个组件的变体（尺寸、状态、类型）
- 定义组件交互状态（默认/悬停/按下/禁用/加载）
- 输出：组件库规范（详见 `references/component-library.md`）

### 步骤 4：页面设计稿生成

- 将设计系统 Token 和组件库应用到原型页面
- 生成每个页面的设计稿（配色、排版、间距标注）
- 标注关键尺寸、间距、阴影等设计参数
- 输出：页面设计稿（HTML/CSS 或标注文档）

### 步骤 5：设计评审

- 自检设计规范的一致性和完整性
- 检查色彩对比度（WCAG 2.1 AA 标准）
- 验证组件库覆盖度是否满足功能清单
- 输出：设计评审报告（问题清单、改进建议）

## 输入输出规范

**输入：**
- 原型 HTML（Phase 06 输出）
- 功能清单（Phase 05 输出）
- 复核报告（Phase 07 输出，可选）

**输出：**
- UI 设计规范文档（色彩、字体、间距、阴影等 Token）
- 页面设计稿（带标注的 HTML/CSS）
- 组件库定义（组件规范、变体、交互状态）
- 设计评审报告
