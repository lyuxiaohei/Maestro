# 架构设计

## 触发条件

- 用户要求进行架构设计（"设计系统架构"、"架构方案"）
- 方案设计完成后进入架构设计阶段（P10）
- 用户提供方案设计文档并要求生成架构设计
- 用户提到 architecture-design

## 执行流程

### 步骤 1：需求确认

- 读取方案设计文档（Phase 09 输出），确认功能范围和约束条件
- 识别关键质量属性（性能、可用性、安全性、扩展性）
- 确认技术约束和非功能性需求
- 输出：架构需求确认清单

### 步骤 2：架构设计

- 确定整体架构风格（分层/微服务/事件驱动等）
- 定义核心组件和组件间交互关系
- 生成架构概览图（详见 `references/architecture-template.md`）
- 输出：架构概览设计

### 步骤 3：模块拆解

- 按业务域拆解功能模块，定义模块边界和职责
- 识别共享模块和跨模块依赖关系
- 生成模块依赖关系图
- 输出：模块拆解方案

### 步骤 4：数据库设计

- 设计核心实体和关系，生成 ER 图
- 定义表结构、索引策略、分区方案
- 评估读写模式和性能要求
- 输出：数据库设计文档

### 步骤 5：API 设计

- 设计 API 接口规范（RESTful/GraphQL/RPC）
- 定义接口路径、请求/响应格式、错误码
- 规划版本管理和认证鉴权策略
- 输出：API 设计文档

### 步骤 6：流程设计

- 设计核心业务流程和异常处理流程
- 绘制时序图和状态流转图
- 标注关键决策节点和边界条件
- 输出：流程设计文档

### 步骤 7：评审基线整理

- 汇总所有设计产出，按架构模板整理（详见 `references/architecture-template.md`）
- 生成评审检查清单，标注关键决策点和风险项
- 输出：架构设计评审基线文档

## 输入输出规范

**输入：**
- 方案设计文档（Phase 09 输出）
- 功能清单（Phase 05 输出，可选）

**输出：**
- 架构设计文档（含架构图、模块图、ER 图、API 文档、流程图）
- 架构评审基线（含检查清单和风险标注）
