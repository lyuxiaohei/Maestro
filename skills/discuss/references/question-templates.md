# 讨论提问模板

定义 AskUserQuestion 的调用格式和选项构建规则。

---

## 提问原则

1. **每轮最多 3 个问题** — 避免用户认知过载
2. **每个问题 2-4 个选项** — 附带简短说明帮助决策
3. **选项需包含语义** — 不只是"是/否"，而是具体方案
4. **记录决策编号** — 每个决策标记为 D-01、D-02... 便于下游引用

---

## 问题构建模板

### 类型 A：方案选择（最常用）

用于"有多个可选方案"的灰色区域。

```
问题: "[灰色区域名称]：[具体问题]？"
选项:
  - label: "方案 A 名称"
    description: "方案 A 的简短说明和适用场景"
  - label: "方案 B 名称"
    description: "方案 B 的简短说明和适用场景"
  - label: "方案 C 名称"
    description: "方案 C 的简短说明和适用场景（如有）"
```

### 类型 B：范围确认

用于"做什么/不做什么"的灰色区域。

```
问题: "本次 [阶段名称] 需要包含以下哪些内容？"
选项: (multiSelect: true)
  - label: "[范围项 1]"
    description: "说明"
  - label: "[范围项 2]"
    description: "说明"
  - label: "[范围项 3]"
    description: "说明"
```

### 类型 C：优先级排序

用于"多个事项需排序"的灰色区域。

```
问题: "[事项类别] 的优先级如何排列？"
选项:
  - label: "[事项 A] 优先"
    description: "先完成 A，B/C 视情况而定"
  - label: "[事项 B] 优先"
    description: "先完成 B，其他延后"
  - label: "并行推进"
    description: "A/B 同步进行"
```

## 讨论流程控制

### 开场

识别灰色区域后，向用户展示：

```
本阶段识别到 N 个需要讨论的决策点：

1. [灰色区域 1 名称]
2. [灰色区域 2 名称]
3. [灰色区域 3 名称]

让我们逐个确认。
```

### 逐区域提问

每轮使用 AskUserQuestion 提 1-3 个问题。用户回答后：
- 记录决策（D-01: 用户选择了 X，原因：...）
- 简短确认："收到。D-01 已锁定：[决策摘要]"
- 进入下一区域

### 跳过处理

用户回答"跳过"或选择"延议"时：
- 记录为延迟项：`D-0N: 延议 — [灰色区域名称]，原因：用户选择延议`
- 不阻塞后续讨论
- 写入 CONTEXT.md 的"延迟项"节

### 收尾

所有区域讨论完毕后，展示决策摘要：

```
讨论完成，共 N 个决策：

| 编号 | 决策 | 内容 |
|------|------|------|
| D-01 | [名称] | [用户选择] |
| D-02 | [名称] | [用户选择] |
| ... | 延议 | [延决议题] |

将写入 P##-CONTEXT.md。确认无误请回复"确认"，需要修改请指出。
```

---

## 决策记录格式

每个决策记录在 CONTEXT.md 的"上下文决策"节：

```markdown
- **D-01:** [决策内容摘要]
  - 原因: [用户给出的原因或自动推断]
  - 影响: [对上下游阶段的影响]
```
