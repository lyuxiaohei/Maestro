# 部署

## 触发条件

- 用户要求进行部署（"准备上线"、"部署到生产"）
- 验收测试通过后进入部署阶段（P18）
- 用户提供验收报告并要求制定部署方案
- 用户提到 deployment

## 执行流程

### 步骤 0：CI/CD 配置检查（新增）

- 检查项目是否已有 CI/CD 配置（.gitlab-ci.yml / .github/）
- 如缺失：调用 ci-template Skill，自动检测技术栈和 CI 平台，生成配置
- 如已有：检查配置是否完整（lint → test → build → deploy）

### 步骤 1：上线准备

- 读取验收报告和架构文档，确认上线条件
- 制定部署方案和回滚策略
- 准备上线检查清单（详见 `references/deployment-checklist.md`）
- 输出：部署方案和上线检查清单

### 步骤 2：生产环境配置

- 配置生产环境（服务器、数据库、中间件）
- 配置环境变量、域名、SSL 证书
- 执行数据库迁移脚本
- 输出：环境配置记录

### 步骤 3：灰度发布

- 按灰度策略发布（按用户比例/地区/功能模块）
- 监控灰度期间系统指标（错误率、响应时间、资源使用）
- 确认灰度结果，决定是否继续扩大范围
- 输出：灰度发布记录和监控报告

### 步骤 4：全量发布

- 灰度验证通过后执行全量发布
- 持续监控生产环境指标
- 确认系统稳定运行，通知相关人员
- 输出：全量发布记录

## 输入输出规范

**输入：**
- 验收报告（Phase 17 输出）
- 架构文档（Phase 12 输出）

**输出：**
- 部署方案、上线检查清单、灰度发布记录、全量发布记录
