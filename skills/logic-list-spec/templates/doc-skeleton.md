# 文档骨架模板 V2.0

整份业务逻辑清单的章节骨架。支持 **正式版** 和 **草案版** 两种模式。

---

## 三、状态标记规范

### 草案标记

| 标记 | 使用位置 | 含义 |
|------|----------|------|
| `[草案]` | 预期结果、状态流转、登录拦截 | 设计意图，未验证 |
| `[待原型]` | 页面标题（H3） | 页面文件名待创建 |
| `[待确认]` | 数据来源、业务问题 | 需用户决策 |
| `[必验]` | 假设清单、业务逻辑增强 | 关键假设，必须验证否则流程失败 |
| `[风险]` | 假设清单、业务逻辑增强 | 可能失败的假设，需关注 |
| `[暂略]` | 假设清单、Not Doing 清单 | 当前版本有意排除 |

### 正式版替换规则

从草案转换为正式版时：

| 草案标记 | 正式版替换 |
|----------|-----------|
| `[草案]` | 移除，替换为源码实现的具体描述（含颜色值、动画名） |
| `[待原型]` | 移除，页面文件名已存在 |
| `[待确认]` | 替换为确认结果，或保留建议答案格式 `（建议：...）` |
| `[必验]`/`[风险]` | 移至业务逻辑增强表，标注验证结果 |
| `[暂略]` | 移至 Not Doing 清单章节或直接移除 |

## 四、骨架使用说明

### 正式版

1. 模块数量和页面数量根据版本范围动态调整
2. 每个页面固定包含截图 + 功能用例表 + 关键字段数据来源
3. 业务逻辑增强表为可选，有业务疑问时才生成
4. 全局章节（页面导航、状态流转）固定在文档末尾
5. 二级标题之间用 `---` 分隔
6. 截图路径始终使用相对路径 `./screenshots/{filename}.png`

### 草案版

1. 必须包含 Not Doing 清单（≥ Doing 的 50%）
2. 每个页面必须包含假设清单（≥ 2 条假设）
3. 假设必须区分 [必验]/[风险]/[暂略]
4. 功能用例预期结果具体且标注 [草案]
5. 不确定数据来源标注 [待确认]
6. 跳转关系和状态流转已定义（标注 [草案]）
7. 无截图，页面标题标注 [待原型]

### 版本号命名

| 模式 | 文件名 |
|------|--------|
| 正式版 | `业务逻辑清单_V{版本号}.md` |
| 草案版 | `业务逻辑清单_V{版本号}-草案.md` |
