# 优先级矩阵定义

本文档定义功能清单优先级评估的两种模型：MoSCoW 分级和影响/紧急度二维矩阵。

---

## MoSCoW 分级标准

| 级别 | 含义 | 判定标准 |
|------|------|---------|
| **Must have** | 必须交付 | 缺少该功能产品无法上线或核心价值无法体现 |
| **Should have** | 应该交付 | 对用户体验或业务价值有显著提升，但短期可降级 |
| **Could have** | 可以交付 | 锦上添花功能，资源和时间充裕时纳入 |
| **Won't have** | 本期不交付 | 明确排除在当前版本范围外，记录备查 |

### 评估维度

每个功能从以下 4 个维度评分（1-5 分）：

- **业务价值**：对核心业务目标的贡献程度
- **用户影响**：影响多少用户、影响频率
- **技术复杂度**：实现难度（反向分，越高越简单）
- **竞品对标**：竞品是否已实现、是否形成差异化

### 评级规则

```
Must have  = 业务价值 >= 4 AND 用户影响 >= 4
Should have = 业务价值 >= 3 AND 用户影响 >= 3
Could have = 其余满足至少 1 个维度 >= 3 的功能
Won't have = 所有维度均 < 3 或明确标注排除
```

## 影响/紧急度二维矩阵

```
         | 紧急度高                | 紧急度低
---------|------------------------|------------------------
影响度高  | Q1: 优先执行（立即启动） | Q2: 计划执行（排入迭代）
影响度低  | Q3: 快速处理（快速交付） | Q4: 延后评估（下版本）
```

### 影响度评分标准（1-5 分）

| 分数 | 标准 |
|------|------|
| 5 | 影响全部用户，核心流程必经环节 |
| 4 | 影响大部分用户，核心功能的关键辅助 |
| 3 | 影响特定用户群，模块内重要功能 |
| 2 | 影响少数用户，边缘场景功能 |
| 1 | 几乎无影响，纯体验优化 |

### 紧急度评分标准（1-5 分）

| 分数 | 标准 |
|------|------|
| 5 | 法规/合规要求，或阻塞其他功能开发 |
| 4 | 市场窗口紧迫，或竞品已形成显著优势 |
| 3 | 按路线图规划节点推进 |
| 2 | 有替代方案，短期可忍受 |
| 1 | 无时间压力，可随时安排 |

---

## 输出格式

优先级矩阵以 Markdown 表格输出：

```markdown
| 功能编号 | 功能名称 | MoSCoW | 影响度 | 紧急度 | 象限 | 备注 |
|---------|---------|--------|-------|-------|------|------|
| F001    | 用户登录 | Must   | 5     | 5     | Q1   |      |
```

象限由影响度和紧急度自动计算，不手动填写。
